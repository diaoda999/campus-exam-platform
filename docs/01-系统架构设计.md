# 01 · 系统架构与模块设计

## 1. 总体分层

平台采用 Maven 多模块单体，模块依赖方向单向向下：

```
exam-admin (启动/Web/定时/MQ 消费)
   └── exam-service (业务逻辑/算法/可靠消息)
          └── exam-mapper (数据访问)
                 └── exam-model (实体/DTO/VO/MQ 消息体)
                        └── exam-common (结果体/枚举/常量/JWT/上下文)
```

选择单体而非微服务的理由：校内场景单场 200 人并发，单体足够承载；模块边界保证内部高内聚低耦合，
热点能力（收卷、统计）通过 MQ 异步化获得接近分布式的削峰收益，部署与运维成本最低。

## 2. 数据模型（题目 → 试卷 → 考试 三级资产链路）

| 表 | 职责 |
|---|---|
| `sys_user` / `sys_class` | 用户（ADMIN/TEACHER/STUDENT 单表角色）、行政班 |
| `knowledge_point` / `question_knowledge` | 知识点、题目-知识点多对多 |
| `question` | 题目主表：题型、题干、选项 JSON、标准答案、解析、难度、引用计数 |
| `paper` / `paper_question` | 试卷模板（总分/时长/组卷方式/状态）、试卷-题目的题目与分值快照 |
| `exam` | 考试：绑定试卷、班级、时间窗口、监考策略 JSON、状态 |
| `exam_record` | 考生考试记录，状态机见文档 03，唯一键 `uk_exam_user(exam_id,user_id)` |
| `exam_answer` | 最终作答与逐题得分（唯一键 `uk_answer(exam_id,user_id,question_id)`） |
| `exam_violation` | 违规记录（切屏等） |
| `score_stat` | 班级维度统计结果持久化（Redis 缓存失效后的兜底） |
| `local_message` | 本地消息表，保障 MQ 投递最终一致 |

试卷保存题目时**冗余分值与题型快照**：组卷后题目再被编辑不影响历史试卷，保证考试可追溯。

## 3. Redis 设计

| Key | 类型 | 用途 | TTL |
|---|---|---|---|
| `exam:token:{uuid}` | String | 一次性考试 Token，值为 `userId:examId` | 考试窗口 |
| `exam:{examId}:user:{userId}` | Hash | 答题快照，field=题目ID，`__meta__` 存元信息 | 考试窗口 |
| `exam:session:{examId}:{userId}` | String | 活动会话，心跳/自动保存滑动续期 | 120s |
| `grade:exam:{examId}:user:{userId}` | Hash | 主观题批改临时成绩 | 24h |
| `stat:class:{classId}:exam:{examId}` | String | 班级统计序列化结果 | 30min |
| `lock:submit:{examId}:{userId}` | String | Redisson 交卷锁 | 30s |
| `mq:idem:{msgKey}` | String | 消费者幂等标记 | 10min |

## 4. RabbitMQ 设计

- Topic 交换机 `exam.exchange`；队列 `exam.collect.queue`（收卷）、`exam.grade.queue`（成绩汇总）、`exam.stat.queue`（统计计算）。
- 每个业务队列绑定死信交换机 `exam.exchange.dlx` 与对应 `.dlq`，重试 3 次仍失败进死信，人工可查。
- 消费端手动 ack，消费成功才确认；`msgKey` 全局幂等，重复投递不产生重复落库。

## 5. Web 与安全

- `JwtInterceptor` 统一拦截 `/api/**`，白名单仅登录、接口文档与健康检查。
- 考试类接口（enter/autosave/heartbeat/violation/submit）在 JWT 之外额外校验 `Exam-Token`：存在性、绑定关系、时间窗、一次性。
- 全局异常处理把业务异常、参数校验异常、未捕获异常统一映射为 `ResultCode`，不向客户端泄漏堆栈。
- `WebLogAspect` 切面记录接口耗时、当前用户与异常，便于教师端/运维定位。

## 6. 前端结构

- Pinia 存登录态（localStorage 持久化），Axios 拦截器自动注入 `Authorization` 与考试期间的 `Exam-Token`。
- 教师端 5 页：题库、试卷与组卷、考试管理、阅卷批改、统计看板；学生端 3 页：考试列表、全屏答题房间、成绩单。
- Vite 开发态 `/api` 代理到 8080，构建产物为纯静态文件，可由任意静态服务器或 Nginx 托管。

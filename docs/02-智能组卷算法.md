# 02 · 智能组卷算法（贪心 + 回溯约束求解）

## 1. 输入约束

教师在前端设定：

- `groups`：每个题型的抽取数量与每题分值；
- `targetDifficulty`：期望整卷平均难度（1~5，支持小数）与容差 `difficultyTolerance`（默认 0.4）；
- `coverage`：指定知识点的最少覆盖题数（硬约束）。

候选集由 `QuestionMapper.selectCandidates` 一次性按题型捞出，避免逐题查库。

## 2. 求解流程

```
1. 候选分桶：按题型把候选题分组，组内按知识点建立倒排索引
2. 硬约束优先（覆盖率）：对每个 (知识点, 最少题数) 约束，
   优先从同时满足题型需求的候选中选取未用题，标记已占用；
   候选不足立即记录为「未满足约束」，绝不拿无关题目凑数
3. 贪心填充：各题型组内按「与当前组平均难度偏差最小」贪心补齐数量
4. 回溯交换逼近目标难度：
   - 计算整卷平均难度，若偏离目标超过容差，
     在「已选偏难题 × 未选偏易题」（或反向）中找使偏差最小的一对交换
   - 设换题上限（默认 200 次），防止组合爆炸，保证秒级返回
5. 输出草稿：题目分组、总分、实际平均难度、未满足约束列表
```

## 3. 关键取舍

- **覆盖率是硬约束、难度是软约束**：知识点覆盖直接影响试卷有效性，优先保证；难度在可行域内逼近，
  无法满足时显式返回 `unmetConstraints`，由教师决定是否放宽，而不是静默产出一张「看似合格」的卷。
- **交换而非重抽**：回溯阶段只做一对一交换，每步都保持题型数量与覆盖率不被破坏，复杂度可控。
- **草稿可微调**：算法产出的是草稿，教师可逐题替换（`replaceQuestion` 只在同题型候选内换题并保持分值），
  满意后再保存为正式试卷，算法负责「80 分的起点」而非替教师做最终决定。

## 4. 单元测试覆盖（PaperGeneratorTest，4 例）

1. 常规约束下各题型数量、总分正确；
2. 知识点硬约束优先被满足；
3. 候选不足时返回未满足约束而非抛错或凑题；
4. 换题后平均难度向目标收敛。

## 5. 复杂度

设候选题总数 N、最终抽题 K：分桶 O(N)，贪心 O(K·N)，交换 O(swapLimit·K)。
题库千题量级下整体为毫秒~秒级，满足「秒级组卷」目标。

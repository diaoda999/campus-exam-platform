## 2. 端到端冒烟实测（2026-09-03，本机真实执行）

中间件以 Docker Compose 启动，后端 `java -jar` 真实连接 MySQL/Redis/RabbitMQ，用 HTTP 请求逐环验证：

| # | 验证点 | 输入 | 实测结果 |
|---|---|---|---|

| 3 | 双 Token 自动保存 | 携带 JWT+Exam-Token | Redis Hash 写入成功 |
| 4 | 断点续考回填 | s2 保存 101/201 后重新进入 | 快照原样回填（101=C、201=ABD） |
| 5 | 缺少 Exam-Token | 只带 JWT | 拒绝，业务码 30003 |
| 6 | 伪造 Exam-Token | 随机 UUID | 拒绝，业务码 30003 |
| 7 | 横向越权 | s3 携带 s2 的 Token | 拒绝（绑定校验），业务码 30003 |
| 8 | 客观题即时出分 | s1 交卷 | 返回客观分 14，与逐题判分明细一致 |
| 9 | 主观题批改/汇总 | 教师对 2 道简答打分 | 异步汇总总分 38 = 客观 14 + 主观 24 |

贪心+回溯组卷六条关键链路，均在真实中间件上端到端跑通，而非仅单元测试或静态代码。

## 4. 200 并发压测（脚本已备，目标环境执行）

脚本 `jmeter/exam-200-concurrency.jmx` 模拟 200 学生、20 秒爬坡，每人执行
「登录 → 进入考试 → 5 次自动保存 → 交卷」完整链路；`jmeter/prepare-200-students.sql` 批量造 stu001~stu200，
`jmeter/testdata/students.csv` 供 CSV 参数化。执行方式见 `jmeter/README.md`。

**设计目标（待压测实测确认，不作为已测结论）：**

| 指标 | 目标值 |
|---|---|
| 登录 P99 | < 300ms |
| 自动保存 P99（Redis 写） | < 100ms |
| 交卷 P99 | < 2s，错误率 0 |
| 200 并发整体 | 无 5xx，Redisson 拦截重复提交，MQ 消息零丢失 |
| 统计看板缓存命中率 | 90%+（Cache-Aside，响应带 fromCache 可直接统计） |

> 说明：本次在开发机完成的是单用户全链路功能冒烟（第 2 节，真实执行并留存证据）；
> 200 人量级的延迟/吞吐数字必须以 JMeter 在目标环境跑出的聚合报告为准，本项目不预先填写未实测的性能数值。

## 5. 已验证边界与已知限制

- 已验证：双 Token 三类非法访问拦截、快照续考、自动收卷、消息最终一致、统计缓存命中、组卷约束求解、客观判分。
- 已知限制（演示定位，非缺陷）：
  - 填空匹配为「归一化精确匹配」，不含语义判分；
  - 权限为单表角色（ADMIN/TEACHER/STUDENT）的轻量模型，未做细粒度 RBAC；
  - 前端为最小演示端，聚焦主流程，不含复杂考务（如考场编排、多端监考视频）。
